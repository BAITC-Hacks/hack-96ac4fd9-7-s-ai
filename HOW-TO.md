# HOW-TO: пошагово, как работаем на хакатоне

A = FRONT (`frontend/`, ветка `front`) · B = BACK (`backend/`, ветка `back`).
У каждого — **один** Codex (роль DEV, `roles/DEV.md`): он сам планирует свои шаги и сам их кодит.
Отдельного оркестратора и кодеров нет — на 5 часов и 2 людей несколько параллельных Codex
в одной папке дают гонки за файлы и порты, а не выигрыш по времени.
Репозиторий для примера называется `hackathon`. Подставьте своё имя.

---

## Шаг 0. Сегодня вечером (каждый, ~20 мин)

1. Установить: **Git**, **Node.js 20+ LTS**, **Windows Terminal** (в Windows 11 он уже есть).
2. Установить Codex CLI:
   ```
   npm i -g @openai/codex
   ```
3. Войти: запустить `codex`, выбрать **Sign in with ChatGPT**, войти в аккаунт с Pro.
4. Настроить имя для коммитов:
   ```
   git config --global user.name "Имя"
   git config --global user.email "почта"
   ```
5. **Репетиция (обязательно):** создать пробный репозиторий, пройти шаги 1–5 ниже
   и убедиться, что `start.ps1` открывает сессию Codex.
6. Ключи OpenAI и NVIDIA держать в заметках. **Не в чате и не в репозитории.**

---

## Шаг 1. Кладём кит в репозиторий хакатона (00:00, делает B)

```
git clone <URL репозитория> hackathon
cd hackathon
```
Скопировать **всё** содержимое `hackathon-kit/` в корень, включая скрытые файлы
`.gitignore`, `.gitattributes`, `.env.example`.
Если у организаторов уже есть `README.md`, наш переименовать в `TEAM.md`.

```
git add -A
git commit -m "chore: team kit"
git push
```

- A должен иметь права на запись в репозиторий (GitHub → Settings → Collaborators).
- Если основная ветка называется `master`, а не `main`, дальше везде вместо `main` пишем `master`.

A (после пуша B):
```
git clone <URL репозитория> hackathon
```

---

## Шаг 2. Настройка (каждый, 1 мин)

```
cd hackathon
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1 -Role front
```
(B пишет `-Role back`.)

Что делает скрипт:
- создаёт твою ветку `front` / `back` и переключает на неё;
- включает проверку перед push;
- создаёт `.env`: **открой его и впиши свои ключи**;
- создаёт рядом папку **`hackathon-main`**, в которой всегда лежит ветка `main`.
  Там делаются мерджи и там работает тестер. **В рабочей папке `hackathon` ветку не переключаем
  никогда**, потому что в ней работает Codex.

Итого у каждого две папки:
```
hackathon/        ← твоя ветка, тут работает твой Codex (DEV)
hackathon-main/   ← ветка main: мерджи, контракт, тестер
```

---

## Шаг 3. Анализ темы и идея (00:00–00:15)

Прежде чем что-то писать в контракт — 15 минут вдвоём на саму идею. Три вещи обязательны:

1. **Смотрим глазами пользователя, не разработчика.** Кто конкретно им пользуется на демо
   (сам жюри в роли пользователя), что ему нужно за 3 клика, что будет вау-моментом.
2. **Своя фишка-отличие.** Не просто «обёртка над GPT» — а что-то одно явное:
   интеграция с внешним сервисом/плагином, или ИИ-чат-бот внутри продукта, или связка
   двух моделей (например OpenAI + NVIDIA) друг с другом. Судьи 2026 года ценят именно
   видимую работу агентов/интеграций больше, чем «ещё один генератор текста».
3. **Прочитать критерии оценки жюри**, если они опубликованы, — до того, как выбирать идею.

Промпт для ChatGPT (Pro):
> Мы на хакатоне, направление «креативные индустрии», 5 часов, 2 человека (фронт и бэк).
> Задача: <текст задачи>.
> Дай 2–3 идеи. Для каждой: (а) кто пользователь и в чём его боль, (б) в чём наша фишка-отличие
> (интеграция с другим сервисом ИЛИ ИИ-чат-бот ИЛИ связка двух моделей), (в) что входит в MVP
> (путь пользователя за 3 минуты демо), а что — уже «если останется время».

Выбираете идею вместе. Записываете в одну строку: **MVP = что именно** и **фишка = что именно**.
Это идёт в шапку `shared/api.md`.

---

## Шаг 4. Контракт вдвоём (00:15–00:30)

1. В том же чате ChatGPT:
   > Теперь заполни shared/api.md и shared/types.ts строго по CONVENTIONS.md для выбранной идеи.
   > MVP-эндпоинты отметь отдельно от эндпоинтов "если останется время".
   > <вставить содержимое CONVENTIONS.md, api.md, types.ts>
2. Правите результат вместе. Эндпоинтов для MVP — **минимум**, только под демо-путь.
3. B вносит контракт в `main`:
   ```
   cd ..\hackathon-main
   git pull
   ```
   Вставить файлы в `shared/`, затем:
   ```
   git add shared
   git commit -m "contract: v1"
   git push
   ```
4. **Оба** подтягивают контракт в свою ветку:
   ```
   cd ..\hackathon
   git pull origin main
   ```

**Любое** изменение контракта позже делается так же: договорились вслух → правка в `hackathon-main`
→ push → оба `git pull origin main` → каждый пишет своему Codex:
«контракт обновлён, перечитай ../shared/».

---

## Шаг 5. Каркас проекта (00:30–00:35, каждый своё)

Команды в `CONVENTIONS.md`, раздел «Скаффолд». A делает `frontend`, B делает `backend`.
Это быстро — 5 минут, дальше сразу MVP. Потом:
```
git add frontend
git commit -m "front: scaffold"
git push -u origin front
```
(B: `git add backend`, `git push -u origin back`.)

Push автоматически запускает проверку. Если она упала, push не пройдёт. Читайте ошибку.

---

## Шаг 6. Запуск Codex

```
powershell -ExecutionPolicy Bypass -File scripts/start.ps1 -Role front
```
Откроется одна вкладка Windows Terminal с Codex в твоей папке.

**Как ИИ получает свою роль:**
- Codex **сам** читает `AGENTS.md` из корня и из папки зоны. Это общие правила и запреты.
- `start.ps1` первым сообщением говорит: «ты DEV зоны FRONT, прочитай roles/DEV.md …».
- `--sandbox workspace-write` физически не даёт агенту писать вне своей папки.

**Что писать в сессию (00:35):**
> Задача хакатона: <текст>. Идея: <1–2 предложения>. Фишка: <что отличает>.
> MVP: <путь пользователя из шага 3>. Контракт в ../shared/.
> Составь TASKS.md: сначала всё, что нужно для MVP end-to-end, потом остальное.
> Установи зависимости и начинай с MVP сразу.

**Разрешения:** Codex иногда спрашивает, можно ли выполнить команду (npm, сеть, запуск сервера).
Нормальные команды разрешайте. `git`, удаление файлов вне задачи и всё подозрительное запрещайте.

**Если `start.ps1` не сработал**, открой вкладку терминала вручную:
```
cd hackathon\frontend
codex --sandbox workspace-write
```
Первым сообщением вставь:
> Ты DEV зоны FRONT. Прочитай ../AGENTS.md, AGENTS.md, ../CONVENTIONS.md, ../roles/DEV.md,
> ../shared/api.md, ../shared/types.ts. Следуй roles/DEV.md: сам планируешь и сам кодишь.

## Шаг 7. MVP-рывок (00:35–01:30, ~1 час без отвлечений)

Единственная цель этого часа — **полный путь end-to-end**, пусть примитивно:
пользователь открывает фронт → вводит запрос → бэк вызывает ИИ → результат показан на экране.
Без стилей, без доп. экранов, без edge-кейсов.

- Каждые ~15–20 минут пишешь Codex «статус». Если он отвечает «можно коммитить: да» —
  коммитишь только свою папку:
  ```
  git add frontend
  git commit -m "front: экран генерации (MVP)"
  git push
  ```
- Push не прошёл? Скопируй ошибку Codex: «check упал, вот вывод: … почини».
- Работайте на моках, пока вторая сторона не готова (`VITE_USE_MOCKS=true`), не ждите друг друга.
- В 01:25 — жёстко остановиться, даже если MVP не идеален. В 01:30 чекпоинт по расписанию.

---

## Шаг 8. Чекпоинт (01:30 и 02:45, ~10 мин)

1. **Оба:** остановите `npm run dev`, закоммитьте и запушьте свою ветку.
2. **B** мерджит бэк в main:
   ```
   cd ..\hackathon-main
   git pull
   git merge origin/back
   git push
   ```
   (Если `git merge` пишет, что ветки не найдены, сначала `git fetch`.)
3. **A** подтягивает main к себе, проверяет, что фронт работает с реальным бэком, и мерджит:
   ```
   cd ..\hackathon
   git pull origin main
   git push
   cd ..\hackathon-main
   git pull
   git merge origin/front
   git push
   ```
4. **B** подтягивает фронт к себе:
   ```
   cd ..\hackathon
   git pull origin main
   ```
5. **Тестер (запускает любой, кто свободен):**
   ```
   cd ..\hackathon-main
   git pull
   ```
   Первый раз — `npm install` в `frontend` и в `backend` этой папки. Затем:
   ```
   powershell -ExecutionPolicy Bypass -File scripts/start.ps1 -Role back -Tester SMOKE
   ```
   Отчёт появится в `hackathon-main/TEST_REPORT.md`. Баги [FRONT] — своему Codex A,
   баги [BACK] — своему Codex B.
6. Оба пишут своим Codex «продолжаем».

**После чекпоинта 01:30 (MVP обязан работать) идёте на 02:45 делать основные фичи
и фишку-отличие из шага 3.** После 02:45 — полировка UI и доп. фичи, A параллельно
начинает слайды.

## Шаг 9. Финал

| Время | Что делать |
|---|---|
| **03:45** | Своим Codex: «FEATURE FREEZE, только фиксы». Чекпоинт по шагу 8, но тестер с `-Tester FULL` |
| **03:50–04:15** | Раздаёте баги из `TEST_REPORT.md` своим Codex. Сначала BLOCKER, потом MAJOR |
| **04:15** | Последний чекпоинт-мердж. После него код в `main` не трогаем |
| **04:15–04:40** | B деплоит из `hackathon-main`. A делает слайды и **записывает видео демо** (страховка) |
| **04:40–05:00** | Репетиция питча вдвоём |

## Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| Закончились лимиты Codex | Перелогиниться в Codex через OpenAI API-ключ (есть $50) |
| Push отклонён (rejected) | `git pull`, затем `git push` |
| Конфликт при мердже | Только в `shared/`: решаете вдвоём, в `hackathon-main` |
| Codex полез не в свои файлы | `git restore <файл>`, напомнить правила из AGENTS.md |
| Codex «потерялся» и тупит | Закрыть вкладку, открыть заново (шаг 6). Контекст хранится в `TASKS.md` |
| ИИ-API упал во время демо | Бэк отдаёт кеш удачных ответов (`backend/data/cache.json`) |
