# Hackathon Kit — 2 человека × 1 Codex каждый × 5 часов

Направление: **креативные индустрии**. Задачу узнаём на месте.

> Почему по одному Codex на человека, а не «армия агентов»: несколько параллельных сессий
> в одной папке делят один working directory — гонки за файлы, порт, `node_modules`. На 5 часов
> и команду из двух человек это не окупается. Один сфокусированный агент, который сам себе
> планировщик и кодер (`roles/DEV.md`), быстрее и надёжнее.

## Кто есть кто

| | Человек A — **FRONT** | Человек B — **BACK** |
|---|---|---|
| Зона | `frontend/` | `backend/` |
| Отвечает за | UI/UX, все экраны, демо-сценарий, **питч и слайды** | API, ИИ-генерация (OpenAI + NVIDIA), данные, **деплой** |
| Ветка | `front` | `back` |
| Codex | 1 сессия DEV | 1 сессия DEV |

Общее: `shared/` (контракт API и типы). Меняете **только вдвоём**, вслух.
Плюс отдельный **тестировщик** — не постоянный, запускается только на чекпоинтах.

## Роли (`roles/`)

- **DEV** — единственный агент своей зоны. Сам планирует шаги в `TASKS.md` и сам их кодит.
- **TESTER** — включается только на чекпоинтах (1:30, 2:45) в режиме SMOKE и в финале (3:45) в режиме FULL,
  всегда на ветке `main` в отдельной папке `<repo>-main`. Между чекпоинтами не работает.

## Когда работает тестировщик

**Три уровня, не на каждый коммит:**

1. **Каждый push → автоматическая проверка без ИИ** (git-хук `pre-push` → `scripts/check.ps1`):
   typecheck + lint + build, ~1 мин. Push не пройдёт, если сломано.
2. **Чекпоинты (1:30, 2:45) → ИИ-тестер SMOKE, ~5 мин.**
3. **Финал (3:45) → ИИ-тестер FULL, ~20 мин**, дальше только фиксы багов.

## Минутный план на 5 часов

| Время | Что происходит |
|---|---|
| **00:00–00:15** | Идея: анализ с точки зрения пользователя, выбор фишки-отличия (интеграция/ИИ-чатбот). Читаем критерии оценки жюри |
| **00:15–00:30** | `shared/api.md` + `shared/types.ts` (контракт), коммит в `main` |
| **00:30–00:35** | Каждый: `setup.ps1`, скаффолд по `CONVENTIONS.md`, коммит скелета |
| **00:35–01:30** | **MVP.** Только путь: пользователь → фронт → бэк → ИИ → результат, целиком, без красоты |
| **01:30** | ЧЕКПОИНТ 1: merge в main, тестер SMOKE. MVP обязан работать end-to-end |
| **01:30–02:45** | Основные фичи и отличие проекта (интеграция / чатбот) |
| **02:45** | ЧЕКПОИНТ 2: merge, SMOKE |
| **02:45–03:45** | Полировка UI, доп. фичи. A начинает слайды |
| **03:45** | **FEATURE FREEZE.** Тестер FULL, дальше только фиксы багов |
| **04:15** | Последний merge в main. Дальше main не трогаем |
| **04:15–04:40** | B: деплой. A: питч, запись видео-демо (страховка) |
| **04:40–05:00** | Репетиция питча вдвоём |

Подробно, с точными командами — в `HOW-TO.md`.

## Как мерджить (чекпоинт)

Мерджи в `main` делаются в отдельной папке `<repo>-main` (создаёт `setup.ps1`). В рабочей папке
ветку **никогда не переключаем** — там работает Codex. Команды — в `HOW-TO.md`, шаг 7.

## Быстрый старт

1. Скопировать папку в репозиторий хакатона (GitHub), `git push`.
2. Каждый: `powershell -ExecutionPolicy Bypass -File scripts/setup.ps1 -Role front` (или `back`).
3. `.env.example` → `.env`, вписать свои ключи.
4. `powershell -ExecutionPolicy Bypass -File scripts/start.ps1 -Role front` (или `back`).
5. В открывшейся сессии: «Задача хакатона: <текст>. Составь TASKS.md и начинай с MVP».
