# AGENTS.md — зона BACK

Корневой `AGENTS.md` и `CONVENTIONS.md` действуют и здесь. Дополнительно:

- Ты в команде **BACK**. Пишешь только в `backend/`.
- Задачи: `backend/TASKS.md`. Статусы: `backend/.status/`.
- **Первым делом (≤15 мин):** `/api/health`, `/api/catalog-options` и `/api/match` должны
  отвечать хотя бы заглушками правильной формы (`ApiResponse<T>` из `shared/types.ts`).
  Тогда фронт сразу переключается на реальный API.
- Датасет: CSV с ~66 профилями подрядчиков (положат люди в `backend/data/`, путь скажут
  в первом сообщении). Поля: `id, anon_name, categories, city, price_from_kzt, event_formats,
  languages, max_hours, busy_dates, description, synthetic, city_imputed, price_imputed`.
  `busy_dates` — список занятых дат в диапазоне 23.09.2026–31.12.2026. `max_hours: null`
  означает «часы не ограничивают участие» (флорист, декоратор и т.п.) — не отсеивай таких
  по длительности. Загружай CSV в память на старте, без базы данных.
- **Порядок обработки `/api/match` — строго так, не переставляй местами:**
  1. Жёсткие фильтры кодом, без LLM: `city`, `category`, `eventType ∈ event_formats`,
     не в `busy_dates` на `eventDate`, `price_from_kzt <= budgetKzt`, и если заданы —
     `language`, `durationHours` (с учётом `max_hours`).
  2. **Бюджет — это порог, а не сигнал качества.** Не ранжируй по близости цены к бюджету:
     подрядчик за 400к не хуже подрядчика за 790к при бюджете 800к.
  3. Из прошедших фильтр выбери до 3 по детерминированному правилу (релевантность
     `description`/формату мероприятию; при равенстве — сортировка по `id`, не случайно).
     Одинаковый вход должен всегда давать одинаковый порядок — это будет проверяться
     повторным запуском с теми же параметрами.
  4. Если по городу+категории вообще нет профилей → `status: 'no_category'`.
     Если профили есть, но 0 прошли остальные фильтры → `status: 'no_match'`, `message`
     называет причину (занятость/бюджет/формат/язык), а не просто «ничего не найдено».
  5. `candidatesBeforeCut` = сколько прошло фильтр до отбора топ-3 (нужно для «показаны
     все 2 из 2» в интерфейсе).
- ИИ вызывай только через `src/ai/index.ts`. **Один batch-вызов на весь запрос**, не по
  одному на карточку — так уложишься в целевые ~10 секунд и объяснения будут естественно
  различаться между собой (модель видит все карточки сразу и должна разграничить их).
  Промпт должен требовать: 1-2 предложения на карточку, привязка к конкретным полям
  (бюджет/язык/длительность/формат/что во free-text description), без «отличный выбор для
  вашего мероприятия» и без выдуманных процентов совпадения.
  OpenAI — основной провайдер, NVIDIA — фолбэк. Таймаут на каждого короткий (~3-4 с суммарно
  на обоих, не 60 с по умолчанию из CONVENTIONS.md — это не укладывается в 10-секундный SLA
  этой задачи), при провале обоих — собери `explanation` из фактов шаблоном без LLM
  (например: "работает на {language}, укладывается в {durationHours} ч, цена от {price} ₸,
  что на {diff} ₸ ниже бюджета"). Ответ должен приходить вовремя даже если оба провайдера легли.
- Для демо закешируй удачные AI-ответы (`backend/data/cache.json` по ключу входных
  параметров), чтобы демо не зависело от сети.
- Хранилище — JSON/CSV-в-памяти, без БД.
- Запросы на изменение контракта пиши в `backend/CONTRACT_REQUEST.md`.
