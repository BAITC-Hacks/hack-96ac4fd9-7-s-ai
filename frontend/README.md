# FRONT — подбор подрядчиков

Один экран на React + TypeScript + Vite + Tailwind. Общие типы импортируются из ../shared/types.ts.
Зависимости ограничены стеком CONVENTIONS и его стандартными Vite/React/TypeScript/Tailwind инструментами.

## Запуск

Из frontend/:

```powershell
npm ci
npm run dev
```

Открыть http://localhost:5173. Dev по умолчанию использует VITE_USE_MOCKS=true, без изменения .env.
Над формой видна пометка о синтетических данных. Каталог приходит через getCatalogOptions().

Для настоящего backend на http://localhost:8787 перезапустить dev:

```powershell
$env:VITE_USE_MOCKS = 'false'
npm run dev
```

Для возврата к мокам задать $env:VITE_USE_MOCKS = 'true' и перезапустить.
Все fetch находятся в src/api/client.ts; /api проксируется на localhost:8787.
Сборка по умолчанию использует реальный API. Для автономной демо-сборки явно задать
VITE_USE_MOCKS=true перед npm run build. При размещении production нужен маршрут /api к backend.

## Демо за 3 минуты

1. Алматы, 14.11.2026, Свадьба, Ведущий, 200000 ₸. Дополнительные поля оставить пустыми.
   Нажать «Найти подходящих»: 3 карточки с разными причинами, видны все три вида dataFlags.
2. В сводке над результатами изменить дату на 15.11.2026 и повторить поиск.
   Остаётся Данияр; message сообщает, что Арман и Алия заняты на эту дату.
3. Дата 16.11.2026: no_match, все трое заняты; причины перечислены.
4. Вернуть 14.11.2026; выбрать категорию Скрипач: единственная Меруерт, показаны все 1 из 1.
5. Выбрать Астану + Ведущий: no_category; предлагается изменить город/категорию.
6. Алматы + Ведущий, 14.11.2026, бюджет 100000: Данияр; 99999: no_match по бюджету.
7. При 200000 и языке English остаётся Алия; при длительности 7 ч также остаётся Алия.

Моки полностью синтетические, не реальные профили. Один ввод возвращает один порядок.
Начальная цена — порог бюджета; она не является оценкой качества.

## Проверки

```powershell
npm run typecheck
npm run check
npm run build
```

checkMocks проверяет сценарии отбора; checkUi — SSR-разметку состояний, карточек,
сводки и формы плюс вызовы mock-клиента; checkClient — fetch-контракт и ошибки.
Нужен Node с поддержкой TypeScript stripping (проверено на Node 24).
Lint не настроен: дополнительных пакетов нет.

Открытый ручной чеклист: ввод формы клавиатурой, все шаги демо выше,
мобильная ширина 375 px, загрузка/двойной submit, backend выключен → ошибка → повтор.
SSR-проверки не заменяют браузерный end-to-end тест. В текущей сессии Computer Use
остановился, поскольку не смог достоверно определить URL браузера.

## Языки интерфейса

В правом верхнем углу — Қазақша / Русский / English. Первый запуск по умолчанию на
казахском; выбор хранится локально в браузере и сохраняется после обновления страницы.
Если localStorage недоступен, переключение продолжает работать в текущем сеансе.
Переведены форма, статусы, ошибки фронтенда, сводка, даты, цены, dataFlags и синтетические
демо-профили с объяснениями. Введённые параметры и язык подрядчика при переключении не меняются.

UI locale использует kk/ru/en; в API язык передаётся как `locale` = kz/ru/en (kk → kz).
Backend возвращает explanation и message на этом языке; цитата из профиля остаётся на русском.
При смене языка с уже показанным результатом в режиме реального API тот же запрос отправляется
повторно с новым locale — карточки и их порядок не меняются, меняется только текст.
Отображаемые подписи известных городов, форматов и категорий переведены, но option.value
остаётся точно таким, как пришёл из getCatalogOptions. Неизвестные значения не подменяются.

checkLocales проверяет три языка на семи сценариях, неизменность фильтрации и payload,
переводы объяснений, формат дат, восстановление языка и fallback при блокировке хранилища.
Ручной чеклист: заполнить поля → сменить три языка → убедиться, что поля сохранились;
выполнить поиск → сменить язык без нового запроса → поменять дату 14 → 15 → 16 ноября;
обновить страницу и проверить язык. Браузерная проверка в этой сессии снова заблокирована
Computer Use: URL браузера не был определён достаточно уверенно.

## Контракт API

candidatesBeforeCut не пересчитывается. В no_match счётчик выводится только при значении
больше нуля; при 0 остаётся сообщение с причиной. Число существующих подрядчиков и причины отсева
приходят в message. Просьба согласовать неоднозначность записана в CONTRACT_REQUEST.md.
После смены даты FRONT не выводит занятость из исчезновения ID: он показывает message backend.

Стандартная настройка Tailwind выполнена по
[официальной инструкции Vite](https://tailwindcss.com/docs/installation/using-vite).

## T14: повтор проверки с настоящим backend

Все города, категории и форматы реального каталога имеют kk/en подписи; API получает
исходные значения. Қазақша дата использует 12 явных названий месяцев (например,
«1 қазан 2026»). Суммы: kk/ru — «1 000 000 ₸», en — «1,000,000 ₸».
Версии прямых зависимостей закреплены по package-lock.json, новые пакеты не добавлялись.

При запущенном backend на 8787 выполнить из frontend/:

```powershell
node scripts/checkLiveBackend.mjs
```

Скрипт включает VITE_USE_MOCKS=false только для своего процесса, поднимает временный
Vite на свободном порту, проверяет клиент через /api proxy и закрывает этот сервер.
Работающий сервер команды и .env не меняются. Проверка включает реальный каталог,
found/no_match и React SSR на трёх языках. Отчёт: .status/t14-backend-check.json.
Интерактивный повтор у тестера: дата 2026-10-01, бюджет 1000000, три языка,
все категории и «Зарубежье»; затем бюджет 1 и отсутствие нулевого счётчика в no_match.
