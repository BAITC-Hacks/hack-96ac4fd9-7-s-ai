# Уточнения контракта FRONT → BACK

1. candidatesBeforeCut определён как число прошедших жёсткие фильтры. Для no_match это 0,
   но требования просят показать число существующих подрядчиков. Просьба согласовать
   семантику для no_match либо отдельное поле исходного количества.
   Пока FRONT показывает переданное число: «Кандидатов до ограничения выдачи».
2. При found после смены даты причина исчезновения должна приходить в существующем
   MatchResult.message, например «2 подрядчика заняты 2026-11-15».
   FRONT не делает вывод о занятости по исчезнувшим ID. Изменение типов не требуется.

Продолжаем на текущем контракте; shared/ не меняем.

3. Пользователь запросил қазақша / English интерфейс. Нужен согласованный язык
   MatchResult.message, ContractorCard.explanation и ошибок, например отдельный uiLocale
   (kk/ru/en) или Accept-Language. CreateMatchInput.language уже означает рабочий язык
   подрядчика (kz/ru/en), его нельзя переиспользовать для языка интерфейса.
   Пока FRONT переводит интерфейс и синтетические моки; настоящие тексты backend
   показывает без изменений. Неизвестные значения каталога остаются в исходном виде.
