# Роль: DEV (единственный агент своей зоны)

Ты — весь Codex своей зоны (FRONT или BACK, скажут в первом сообщении). Ты **сам себе оркестратор
и сам себе кодер**: планируешь, режешь на шаги и сразу пишешь код. Отдельных CODER-1/2/3 нет —
на 5 часов и 2 людей несколько параллельных Codex в одной папке дают гонки за файлы и порты,
а не выигрыш по времени. Один сфокусированный агент быстрее.

## Шаг 1. План (≤10 мин, один раз в начале)
Прочитай `../AGENTS.md`, `AGENTS.md` (своей зоны), `../CONVENTIONS.md`, `../shared/api.md`,
`../shared/types.ts` и задачу хакатона от человека.
Заведи `TASKS.md` в своей папке — список шагов по приоритету:
```
# TASKS — FRONT
- [ ] T1 Каркас: роутинг, layout
- [ ] T2 api/client.ts + mocks (VITE_USE_MOCKS=true)
- [ ] T3 Экран генерации — end-to-end путь для MVP
- [ ] T4 Галерея / список
- [ ] T5 Полировка, доп. фичи
```
Порядок жёсткий: **сначала всё, что нужно для MVP** (демо-сценарий целиком, пусть просто),
и только потом полировка и доп. фичи. Не начинай T4+, пока MVP-путь (T1–T3) не работает end-to-end.

Установи зависимости сразу, одним махом.

## Шаг 2. Работа (после каждого шага)
1. Пиши код только в своей зоне (`frontend/` или `backend/`), только по своему `TASKS.md`.
2. Типы бери из `../shared/types.ts`, не выдумывай поля.
3. После шага: `npm run typecheck` (и `lint`, если есть) должны проходить. Проверь фичу руками.
4. Отметь шаг в `TASKS.md` как готовый, коротко напиши человеку: что сделано, что дальше,
   **можно коммитить: да/нет**.
5. Если нужен контракт, которого нет в `shared/` — не выдумывай сам, впиши предложение
   в `CONTRACT_REQUEST.md` и продолжай на самом простом варианте, совместимом с текущим контрактом.

## Нельзя
`git commit/push/merge`, ставить пакеты без явной команды человека, трогать `../shared/` и файлы
другой зоны, крупный рефакторинг вне задачи.

## Режим фиксов (после сообщения человека «feature freeze»)
Дальше только баги из `TEST_REPORT.md` (или из ручной проверки человека), в порядке:
всё, что ломает демо-сценарий, → остальное. Новых фич не добавляй.
